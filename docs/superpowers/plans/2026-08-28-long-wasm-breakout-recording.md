# Long WASM Breakout Recording Implementation Plan

> **For agentic workers:** Parallel execution: use `ultrapowers:ultrapowers` (this plan carries ultraplan markers). Sequential fallback: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate, upload, document, and push a proper long WASM Breakout asciinema recording matching the Python recording workflow.

**Architecture:** Extend `tools/videos/generate.py` with a `breakout-wasm` video target that uses the same deterministic driver as the existing Breakout recording but runs `mise run wasm`. Add tests that reject short/synthetic/trap-output casts and require the task surface to expose the new video target. If the long WASM run exposes runtime stack limits, fix the WASM task/runtime path so the real generated recording completes.

**Tech Stack:** Python 3.14, pytest, mise, asciinema v2, Rust/WASI, Wasmtime.

**Spec:** User-approved chat design, 2026-08-28: make a proper long WASM Breakout video like the Python version, with a mise task and README upload link.

**Acceptance:** suite — generator/task tests plus recording artifact tests verify a real long timed WASM cast, and the uploaded URL is linked from `examples/README.md`.

## Global Constraints

- The WASM Breakout recording must be generated by a real `asciinema rec` command, not hand-built as a synthetic three-frame JSON file.
- The WASM Breakout recording must use `mise run wasm examples/breakout.thor` with a deterministic `--clock <path>` driver.
- `examples/README.md` must link the uploaded hosted asciinema URL and the committed local cast.
- Existing `mise run generate-video breakout` behavior must remain intact.
